# Test cases: The Cursed Village 1996

แผนทดสอบนี้ครอบคลุมการเล่นแบบหลายคนตั้งแต่สร้างห้องจนจบเกม ทั้งกติกา การ์ด การเชื่อมต่อ และหน้าเว็บ แบ่งเป็น unit/integration tests สำหรับตรรกะฝั่ง server และ end-to-end tests ที่ใช้ browser หลายหน้าต่าง

## วิธีเตรียมชุดทดสอบ

- ใช้ห้องทดสอบและผู้เล่นจำลอง 4–12 คน ห้ามต่อกับห้องหรือข้อมูล production
- กำหนด seed หรือ fixture สำหรับลำดับการ์ด เพื่อให้ผลทดสอบซ้ำได้ โดยไม่พึ่งการสุ่มจริง
- สร้างผู้เล่นแต่ละคนด้วย browser context/socket แยกกัน ตรวจ state ของทุกคนหลัง action สำคัญ
- เก็บหลักฐานอย่างน้อย: phase, current turn, จำนวน/ตำแหน่งการ์ด, alive, winner และข้อความ error ใน server log
- ระบุผลที่คาดหวังตามกติกาปัจจุบันของโปรเจกต์ โดยเฉพาะเงื่อนไขชนะชาวบ้าน: การ์ด Witch ที่ยังซ่อนหมด และยังมีชาวบ้านที่ไม่เคยติดเชื้อรอดอยู่

## แนวทางจัดลำดับการทำจริง

1. เริ่มจาก P0 เป็น automated tests ของ `startGame`, `playCard`, `resolveNightActions`, `handlePlayerDeath`, `checkWinCondition` และ Socket.IO event guards

3. ทำ card tests ทีละใบโดย fixture กำหนด deck/hand แทนการรอจั่วสุ่ม

5. ให้ `npm test` ล้มเหลวเมื่อไม่มี test cases แทน `--passWithNoTests` เพื่อป้องกัน CI ผ่านทั้งที่ไม่มีการตรวจจริง

## จุดที่ต้องตัดสินใจ/ทวนก่อนล็อก expected result

- ใช้กติกาใน `src/server/game/` เป็น source of truth สำหรับ expected result; โค้ด legacy ถูกลบแล้ว
- กรณีเปิด Witch ใบสุดท้ายแต่ไม่มีชาวบ้านที่ไม่เคยติดเชื้อรอด ควรกำหนด precedence ให้ชัดว่า Witches ชนะ, Draw หรือ Townsfolk ชนะ
- ทดสอบความต่างของการเลือก self-target ตามชนิดการ์ดให้ตรงกับกติกาฉบับที่เกมใช้จริง
- การหมดเวลา/ไม่เลือก Night action และการตาย/หลุดระหว่างรอ prompt ต้องมีนโยบายชัด เพื่อให้คาดหวังผลได้แน่นอน
