# หมู่บ้านต้องสาป 1996 · Halloween Edition

เกมการ์ดออนไลน์หลายผู้เล่นแบบเรียลไทม์ ได้แรงบันดาลใจจาก **Salem 1692** และดัดแปลงเป็นธีมหมู่บ้านลับแล จังหวัดอุตรดิตถ์ ปี 1996 สำหรับเล่นกับเพื่อนและเรียนรู้การพัฒนาเกม

**ผู้เล่น:** 4–12 คนต่อห้อง รวมบอท · **มุมมอง:** 2D และโต๊ะ 3D แบบเลือกเปิดได้

## เริ่มเล่นในเครื่อง

ตัวอย่างนี้ใช้ **Node.js 24** ให้ตรงกับสภาพแวดล้อมพัฒนาปัจจุบัน และ npm โดย `package.json` ระบุ engines ขั้นต่ำเป็น Node.js 18 และ npm 8

```bash
git clone https://github.com/8xecute/The-cursed-village-1996.git
cd The-cursed-village-1996
npm install
npm start
```

เปิด **http://localhost:3000** แล้วตั้งชื่อและสร้างห้อง

- `npm install` จะ build ไฟล์ผ่าน `postinstall` ให้อัตโนมัติ จึงต้องติดตั้ง devDependencies สำหรับขั้นตอน build ด้วย
- `npm start` จะสร้าง bundle 3D ผ่าน `prestart` ก่อนเปิด server
- ถ้ากำหนดตัวแปร `PORT` ให้เปิดเว็บด้วยพอร์ตนั้นแทน 3000
- เปิดผ่าน server ตามขั้นตอนนี้ เพราะหน้าเว็บใช้ ES modules และ Socket.IO

### ลองเล่นหลายคน

1. ผู้สร้างห้องส่งลิงก์ห้องให้ผู้เล่นคนอื่น
2. สำหรับทดสอบในเครื่องเดียว ให้ใช้ browser profiles หรือคนละเบราว์เซอร์ เพื่อแยกตัวตนผู้เล่นที่เก็บใน localStorage
3. หัวห้องเพิ่มบอทได้ในล็อบบี้ และเป็นผู้มีสิทธิ์เตะบอท
4. เริ่มเกมเมื่อมีผู้เล่นอย่างน้อย 4 คน

การเปิดหลายแท็บใน browser profile เดียวกันใช้ localStorage ร่วมกัน จึงไม่เหมาะสำหรับจำลองผู้เล่นหลายคน

## ฟีเจอร์ปัจจุบัน

### ห้องและผู้เล่น

- สร้างห้อง ดูรายการห้อง และเข้าร่วมผ่านลิงก์เชิญ
- ระบบพร้อมเล่นและบอทเติมห้อง รองรับรวมสูงสุด 12 คน
- ล็อกการเปลี่ยนชื่อเมื่อเข้าห้อง
- ผู้เข้าหลังเริ่มเกมเป็นผู้ชม โดย server กรองข้อมูลลับตามผู้รับ
- รอผู้เล่นเชื่อมต่อใหม่สูงสุด 2 นาทีหลังหลุด
- รีเฟรชแล้วพยายามกลับสู่ห้องและมุมมองเดิม โดยไม่เปิดหน้าเข้าสู่หมู่บ้านซ้ำ
- โฮสต์ตั้งชีวิต 1–5 ใบและปอบ 1–4 ใบได้ หรือใช้ค่าตามจำนวนคน จำนวนปอบต้องน้อยกว่าจำนวนผู้เล่น
- รวมการลบห้องไว้ใน `game.deleteRoom()` เพื่อเคลียร์ timer, บอท และสมาชิก Socket.IO

### ระหว่างเกม

- สับและแจกชีวิตทีละคน ดูฝั่งและสลับตำแหน่งชีวิตได้ก่อนทุกคนกดยืนยัน จากนั้นปอบมอบเครื่องเซ่นและเริ่มกลางคืนแรก
- จั่ว/เล่นการ์ด ข้อกล่าวหา การเปิดการ์ดชีวิต และสถานะการตาย
- ปุ่มจบเทิร์นต้องผ่านเงื่อนไข action ของเทิร์นก่อน มีการยืนยันจั่วและจบเทิร์นเพื่อช่วยป้องกันแตะพลาด
- ปอบมาร์คเป้าหมายให้ทีมเห็นก่อน ปอบคนใดก็ยืนยันสังหารได้ โดยต้องยืนยันอีกครั้งและเลือกได้หนึ่งเป้าหมายต่อคืน
- แชททีมปอบอยู่ในหน้าต่างเลือกสังหารด้วย
- ผู้ได้รับการ์ดปอบจากพิธีเซ่นไหว้รู้จักผู้ส่งก่อน และรู้จักทีมที่เหลือเมื่อเข้ากลางคืน จากนั้นจำสมาชิกที่รู้จักตลอดเกม
- เลือกสารภาพหรือข้ามช่วงก่อนรุ่งสาง โดยค่าเริ่มต้นไม่มีการนับถอยหลัง คนที่หมอผีปกป้องหรือมีที่หลบภัยผ่านขั้นนี้อัตโนมัติโดยไม่เสียการ์ดชีวิต และประวัติไม่ระบุชื่อเป้าหมายที่รอดจากการสังหาร
- หน้าสรุปจบเกมเปิด/ปิดได้ และแสดงฝ่าย สถานะและการ์ดชีวิตของผู้เล่น
- ผู้เล่นที่ตายส่งภาพหลอกให้คนที่ยังมีชีวิตได้ทุก 2 นาที มีเวลานับถอยหลังและเก็บคูลดาวน์ฝั่งเซิร์ฟเวอร์
- เสียงเตือนเทิร์นแยกจากเพลงและเอฟเฟกต์ มีสวิตช์และปุ่มลองเสียงในตั้งค่า เตือนได้เมื่อสลับแท็บและหน้าเว็บยังทำงานอยู่ ต้องมีการแตะ/คลิกหน้าเว็บก่อน มือถือที่ระบบพักเบราว์เซอร์อาจไม่ได้รับเสียงทันที
- ลูกซองลับแขวนอยู่ในฉาก 3D หยิบได้ครั้งเดียวต่อเกม ใช้ได้ 2 นาทีต่อเนื่องหลังหยิบ ยิงได้ช่วงกลางวันที่ไม่มีแอ็กชันค้าง หมดเวลาแล้วหยิบซ้ำไม่ได้ การยิงทำให้เป้าหมายตายและมีผลต่อผลแพ้ชนะ

### การแสดงผล

- ธีมหมู่บ้านไทย ฟอนต์ไทยและชื่อรุ่น Halloween Edition โทนส้ม–ม่วง ใช้ภาพการ์ดชุดใหม่
- “สอนเล่น” มีแบบเร็ว 10 บทและแบบเต็ม 24 บท ครบการ์ด 18 ชนิด บันทึกความคืบหน้าแยกหลักสูตรในอุปกรณ์
- บทสอนบอกสิ่งที่ต้องกดครั้งละขั้น เลือก 2D หรือ 3D เต็มหน้าจอได้ เป็นฉากจำลองแยกจากห้องจริง หากอยู่ในห้องต้องออกก่อนเริ่มฝึก
- “คู่มือและการ์ด” รวมกติกากับรายละเอียดการ์ด ส่วน “อัพเดท” เปิดบันทึกการเปลี่ยนแปลงสำหรับผู้เล่น
- แถบคำแนะนำสั้นตามสถานการณ์ แจ้งเมื่อถึงตาคุณ และบอกขั้นตอนถัดไป พร้อมปุ่มกลับไปดูการ์ด
- รองรับคอมและมือถือ: 2D แยกแท็บการ์ด ผู้เล่นและข้อความ ย่อข้อมูลชีวิตในบอร์ดผู้เล่น; 3D แยกพื้นที่ฉากกับปุ่มด้านล่างเพื่อลดการเลื่อนหน้า
- หน้าต่าง action บางช่วงย่อได้เพื่อดูกระดานด้านหลัง
- ปรับเพลงและเอฟเฟกต์แยกกัน เพลงหยุดเมื่อซ่อนหน้าเว็บหรือสลับแอป และเงียบระหว่างแจกชีวิตก่อนเริ่มเพลงช่วงมอบเครื่องเซ่น
- 3D มีตัวละคร 12 แบบจากโมเดลฐานสองตัว สุ่มไม่ซ้ำในห้อง ผู้ตายฟุบบนโต๊ะและเป็นสีเทา พร้อมฉากยิงลูกซองและกองเลือด
- ลากเมาส์ซ้ายหมุนรอบโต๊ะ คลิกขวาค้างแล้วลากเพื่อเงย/ก้ม ล้อเมาส์ซูม และ WASD เลื่อนกล้อง; มือถือลากนิ้วหมุนและจีบสองนิ้วซูม
- ปุ่มกล้องแยกแถวจากหยิบ/วางไพ่ จัดไพ่ ขนาดไพ่และจบเทิร์น; ปุ่มเล็งลูกซองอยู่มุมล่างซ้าย ข้อความแจ้งการยิงอยู่ด้านบน
- ปรับขนาดชีวิต ไพ่ในมือและสถานะได้ 50–200% เก็บค่าในอุปกรณ์ ขนาดไพ่ในมือมีผลเฉพาะของเรา; ยก/วางและจัดลำดับไพ่ในมือได้
- ชีวิตที่เปิดยังอยู่ตำแหน่งเดิม มีกรอบสีและกากบาทใน 3D ชื่อผู้เล่นที่ถึงเทิร์นมีแสงเรือง
- เลือกคุณภาพ 3D ต่ำ กลาง สูงได้ทุกอุปกรณ์ ไม่กำหนดเพดานเฟรมเรต; กลางวันนอกหน้าต่างครึ้มสว่าง กลางคืนดับไฟบ้านและใช้แสงเทียน
- เลือกผู้เล่น ชีวิตและสถานะบนโต๊ะได้ พร้อมแผงยืนยันแต่ละช่วง แถบแจ้งการใช้การ์ด และประวัติเหตุการณ์ที่เน้นข้อความเกี่ยวกับเรา
- 3D โหลดเมื่อต้องใช้ และใช้กติกาเดียวกับมุมมอง 2D

## กติกาโดยย่อ

เกมแบ่งเป็น **ทีมชาวบ้าน** และ **ทีมปอบ** ส่วนการ์ดหมอผี (`Constable`) ให้ความสามารถป้องกันตอนกลางคืน ไม่ใช่ฝ่ายชนะที่สาม

### ลำดับการเล่น

1. **เตรียมเกม:** แจกชีวิต ดูฝั่ง จัดตำแหน่งและยืนยันให้ครบทุกคน แล้วปอบมอบเครื่องเซ่น
2. **กลางคืนแรก:** ทีมปอบเลือกและยืนยันเหยื่อ หมอผีเลือกปกป้องผู้อื่น โดยเลือกตัวเองไม่ได้
3. **ก่อนรุ่งสาง:** ทุกคนที่มีสิทธิ์เลือกสารภาพหรือข้าม ระบบรอให้ตัดสินใจครบก่อนเปิดผลและเริ่มวันใหม่
4. **กลางวัน:** เลือกจั่ว 2 ใบหรือเล่นการ์ด จั่วครบแล้วจบเทิร์นอัตโนมัติ หากเล่นการ์ดให้กดจบเทิร์น เมื่อจั่วได้ยามวิกาลจึงเข้าสู่กลางคืนรอบถัดไป

การ์ด **พิธีเซ่นไหว้** ทำให้เกิดขั้นตอนเปิดการ์ดของผู้ถือเครื่องเซ่นและส่งต่อการ์ดชีวิตจากผู้เล่นทางซ้าย การเคยได้รับการ์ดปอบทำให้เป็นทีมปอบถาวร แม้ส่งการ์ดต่อแล้ว

- เล่นการ์ดแดงหลายใบพร้อมกันได้ แต่การ์ดที่ออกจากมือในแอ็กชันเดียวรวมไม่เกิน 7 แต้ม เมื่อแต้มเป้าหมายถึง 7 จะเปิดชีวิตเพียง 1 ใบ หากรอดจะล้างการ์ดแดงและแต้ม ต้องเล่นแอ็กชันใหม่เพื่อเปิดใบถัดไป
- ข้อแก้ต่างนำการ์ดแดงชนิดเดียวกันออกได้รวมไม่เกิน 3 แต้ม เช่น ข้อกล่าวหา 3 ใบหรือหลักฐาน 1 ใบ
- การ์ดเหตุการณ์นับเป็นหนึ่งใบที่จั่ว หลังจบเหตุการณ์จั่วต่อเฉพาะจำนวนที่เหลือให้ครบ 2 ใบ
- ชีวิตอัตโนมัติ: 4–7 คน คนละ 5 ใบ / 8–9 คน คนละ 4 ใบ / 10–12 คน คนละ 3 ใบ; ปอบอัตโนมัติ: 4–5 คน 1 ใบ / 6–12 คน 2 ใบ

### เงื่อนไขจบเกมในโค้ดปัจจุบัน

- **ปอบชนะ:** ยังมีผู้รอดชีวิต และผู้รอดชีวิตทั้งหมดเคยเป็นปอบ
- **ชาวบ้านชนะ:** ไม่มีการ์ดปอบที่ยังไม่เปิดเหลือในเกม และยังมีผู้รอดชีวิตที่ไม่เคยเป็นปอบ
- **เสมอ:** ไม่มีผู้รอดชีวิต
- **ยุติเกมกรณีคนออก:** มีเส้นทางจบเกมเมื่อคนออกหมดหรือเหลือไม่พอเล่น โดยบันทึกเหตุผลแยกจากผู้ชนะปกติ

จำนวน 4 คนเป็นขั้นต่ำสำหรับ **เริ่มเกม** ไม่ใช่เงื่อนไขจบเกมทันทีเมื่อผู้รอดชีวิตลดต่ำกว่า 4 คน

รายละเอียดที่ใช้ตัดสินจริงอยู่ใน `src/server/game/outcome.js` และการจัดการคนออกใน `src/server/game/rooms.js`

### กลุ่มการ์ด

- **แดง:** ข้อกล่าวหา (+1), หลักฐาน (+3), พยาน (+7)
- **เขียว:** แพะรับบาป คำสาป ข้อแก้ต่าง ช่วงชิง พันธนาการ และวางเพลิง
- **น้ำเงิน:** เครื่องเซ่น ที่หลบภัย พลังศรัทธา และผูกวิญญาณ
- **ดำ:** พิธีเซ่นไหว้และยามวิกาล
- **การ์ดชีวิต:** ชาวบ้าน ปอบ และหมอผี

จำนวนการ์ดในสำรับดูที่ `src/shared/cards.js` อ่านความสามารถแต่ละใบได้จากเมนู “คู่มือและการ์ด” ในเว็บ

ดูหน้าที่แต่ละ module และแนวทางเพิ่มฟีเจอร์ใน [CODE_MAP_TH.md](docs/CODE_MAP_TH.md)

## คำสั่งที่ใช้บ่อย

```bash
npm start                         # เปิด server; build 3D ก่อนเริ่ม
npm run dev                       # เปิดด้วย nodemon; build 3D ก่อนเริ่ม
npm run build:client              # build 3D (ชื่อคำสั่งเดิมสำหรับ deploy)
npm run build:3d                  # build เฉพาะฉาก Three.js
npm run health                    # ตรวจไฟล์และ syntax
node scripts/check-witch-night.cjs # integration check ระบบกลางคืน
```

- `npm run build:render` เรียก build ฝั่ง client เช่นเดียวกัน
- `npm run build`, `build:client` และ `build:render` สร้างเฉพาะ bundle 3D; server รันจาก source โดยตรง
- `npm test` ใช้ Jest พร้อม `--passWithNoTests` จึงอาจผ่านได้แม้ไม่มี test cases
- `npm run lint` มีอยู่ แต่การตั้งค่า ESLint เดิมยังใช้ `sourceType: script` จึงต้องปรับให้รองรับ ES modules ก่อนใช้เป็นเกณฑ์ตรวจทั้งโปรเจกต์
- `optimize:assets` ยังเป็น placeholder ไม่ได้บีบอัดรูปหรือเสียงให้

### สถานะการตรวจสอบ

มีสคริปต์ integration สำหรับระบบกลางคืน (`scripts/check-witch-night.cjs`) และตรวจบทสอนด้วยเบราว์เซอร์ (`scripts/check-training-ui.cjs`) สคริปต์บทสอนรับโฟลเดอร์เก็บภาพเป็นอาร์กิวเมนต์ ใช้ Playwright และ Chromium ที่ติดตั้งแยก โดยกำหนดตำแหน่งผ่าน `PLAYWRIGHT_MODULE` และ `CHROME_PATH` ได้

ล่าสุดตรวจบทสอนแบบเร็ว 10 บทและแบบเต็ม 24 บทใน 2D/3D รวมหน้าจอคอม มือถือแนวตั้งและแนวนอนแล้ว การตรวจนี้เป็นฉากฝึกจำลอง ไม่ใช่ผลทดสอบเกมหลายผู้เล่นตลอดเกม ดูแผนกรณีอื่นใน [TEST_CASES.md](docs/TEST_CASES.md)

## Deploy บน Render

ใช้ Web Service ที่รัน Node.js จาก repository นี้:

```text
Build Command: npm ci --include=dev
Start Command: npm start
```

`npm ci --include=dev` ใช้ `package-lock.json` ติดตั้งเครื่องมือ build และเรียก `postinstall` เพื่อ build bundle 3D

- ใช้ Node.js 24 ให้ตรงกับตัวอย่างการพัฒนา
- server อ่านพอร์ตจาก `PORT` ของระบบ โดยมีค่าเริ่มต้น 3000
- หน้าเว็บปัจจุบันให้บริการจาก `public/` ด้วย native ES modules; webpack สร้างเฉพาะ bundle 3D ใน `public/`
- ต้องเป็น server ที่รัน Node.js และ Socket.IO จึงจะสร้างห้องและเล่นหลายคนได้
- ห้องและเกมเก็บในหน่วยความจำของ process การ restart หรือ deploy ใหม่ทำให้ห้องเดิมหาย
- โครงสร้างปัจจุบันใช้ room store ใน process เดียว หากขยายหลาย instance ต้องออกแบบ shared state และการเชื่อมต่อเพิ่มเติม

ไม่ควรแก้ `public/table3d.bundle.js` หรือ `node_modules` โดยตรง ให้แก้ source แล้ว build ใหม่
