# หมู่บ้านต้องสาป 1996

เกมการ์ดออนไลน์หลายผู้เล่นแบบเรียลไทม์ ได้แรงบันดาลใจจาก **Salem 1692** และดัดแปลงเป็นธีมหมู่บ้านลับแล จังหวัดอุตรดิตถ์ ปี 1996 สำหรับเล่นกับเพื่อนและเรียนรู้การพัฒนาเกม

**ผู้เล่น:** 4–12 คนต่อห้อง รวมบอท · **มุมมอง:** 2D และโต๊ะ 3D แบบเลือกเปิดได้

[เว็บเกม](https://the-cursed-village-1996.onrender.com/) · [แผนที่โค้ด](docs/CODE_MAP_TH.md) · [สถานการณ์ทดสอบ](docs/TEST_CASES.md)

> README นี้อ้างอิงโค้ดใน repository ณ วันที่ **16 ตุลาคม 2026** ฟีเจอร์บนเว็บ Production ขึ้นอยู่กับ commit ที่ deploy ล่าสุด

## เริ่มเล่นในเครื่อง

ตัวอย่างนี้ใช้ **Node.js 24** ให้ตรงกับสภาพแวดล้อมพัฒนาปัจจุบัน และ npm โดย `package.json` ระบุ engines ขั้นต่ำเป็น Node.js 18 และ npm 8

```bash
git clone <repository-url>
cd The-cursed-village-1996
npm install
npm start
```

เปิด **http://localhost:3000** แล้วตั้งชื่อและสร้างห้อง

- `npm install` จะ build ไฟล์ผ่าน `postinstall` ให้อัตโนมัติ จึงต้องติดตั้ง devDependencies สำหรับขั้นตอน build ด้วย
- `npm start` จะสร้าง bundle 3D ผ่าน `prestart` ก่อนเปิด server
- ถ้ากำหนดตัวแปร `PORT` ให้เปิดเว็บด้วยพอร์ตนั้นแทน 3000
- เปิดผ่าน server ตามขั้นตอนนี้ เพราะหน้าเว็บใช้ ES modules และ Socket.IO

### ลองเล่นหลายคน

1. ผู้สร้างห้องส่งลิงก์ห้องให้ผู้เล่นคนอื่น
2. สำหรับทดสอบในเครื่องเดียว ให้ใช้ browser profiles หรือคนละเบราว์เซอร์ เพื่อแยกตัวตนผู้เล่นที่เก็บใน localStorage
3. หัวห้องเพิ่มบอทได้ในล็อบบี้ และเป็นผู้มีสิทธิ์เตะบอท
4. เริ่มเกมเมื่อมีผู้เล่นอย่างน้อย 4 คน

การเปิดหลายแท็บใน browser profile เดียวกันใช้ localStorage ร่วมกัน จึงไม่เหมาะสำหรับจำลองผู้เล่นหลายคน

## ฟีเจอร์ปัจจุบัน

### ห้องและผู้เล่น

- สร้างห้อง ดูรายการห้องที่ยังไม่เริ่ม และเข้าร่วมผ่านลิงก์เชิญ
- ระบบพร้อมเล่นและบอทเติมห้อง รองรับรวมสูงสุด 12 คน
- ล็อกการเปลี่ยนชื่อเมื่อเข้าห้อง
- ผู้เข้าหลังเริ่มเกมเป็นผู้ชม โดย server กรองข้อมูลลับตามผู้รับ
- รอผู้เล่นเชื่อมต่อใหม่สูงสุด 2 นาทีหลังหลุด
- รวมการลบห้องไว้ใน `game.deleteRoom()` เพื่อเคลียร์ timer, บอท และสมาชิก Socket.IO

### ระหว่างเกม

- จั่ว/เล่นการ์ด ข้อกล่าวหา การเปิดการ์ดชีวิต และสถานะการตาย
- ปุ่มจบเทิร์นต้องผ่านเงื่อนไข action ของเทิร์นก่อน มีการยืนยันจั่วและจบเทิร์นเพื่อช่วยป้องกันแตะพลาด
- ปอบมาร์คเป้าหมายให้ทีมเห็นก่อน ปอบคนใดก็ยืนยันสังหารได้ โดยต้องยืนยันอีกครั้งและเลือกได้หนึ่งเป้าหมายต่อคืน
- แชททีมปอบอยู่ในหน้าต่างเลือกสังหารด้วย
- ผู้ได้รับการ์ดปอบจากพิธีเซ่นไหว้รู้จักผู้ส่งก่อน และรู้จักทีมที่เหลือเมื่อเข้ากลางคืน จากนั้นจำสมาชิกที่รู้จักตลอดเกม
- เลือกสารภาพหรือข้ามช่วงก่อนรุ่งสาง โดยค่าเริ่มต้นไม่มีการนับถอยหลัง
- หน้าสรุปจบเกมเปิด/ปิดได้ และแสดงฝ่าย สถานะและการ์ดชีวิตของผู้เล่น

### การแสดงผล

- แถบคำแนะนำสั้นตามสถานการณ์ แจ้งเมื่อถึงตาคุณ และบอกขั้นตอนถัดไป พร้อมปุ่มกลับไปดูการ์ด
- เลย์เอาต์สำหรับเดสก์ท็อปและมือถือ พร้อมแท็บการ์ด ผู้เล่น และข้อความ
- หน้าต่าง action บางช่วงย่อได้เพื่อดูกระดานด้านหลัง
- ปรับระดับเสียงและจำค่าไว้ในอุปกรณ์
- สลับโต๊ะ 3D ได้ หมุนมุมมอง ซูมด้วยล้อเมาส์ และกดการ์ด/กองจั่วบนโต๊ะ
- 3D โหลดเมื่อต้องใช้ และใช้กติกาเดียวกับมุมมอง 2D

## กติกาโดยย่อ

เกมแบ่งเป็น **ทีมชาวบ้าน** และ **ทีมปอบ** ส่วนการ์ดหมอผี (`Constable`) ให้ความสามารถป้องกันตอนกลางคืน ไม่ใช่ฝ่ายชนะที่สาม

### ลำดับการเล่น

1. **กลางวัน:** จั่วหรือเล่นการ์ดตามเงื่อนไขเทิร์น ใช้ข้อกล่าวหาและความสามารถการ์ด
2. **กลางคืน:** ทีมปอบเลือกและยืนยันเหยื่อ หมอผีเลือกผู้ป้องกัน
3. **ก่อนรุ่งสาง:** ผู้เล่นที่มีสิทธิ์เลือกสารภาพหรือข้าม จากนั้นระบบสรุปผลกลางคืนและเริ่มวันใหม่

การ์ด **พิธีเซ่นไหว้** ทำให้เกิดขั้นตอนเปิดการ์ดของผู้ถือเครื่องเซ่นและส่งต่อการ์ดชีวิตจากผู้เล่นทางซ้าย การเคยได้รับการ์ดปอบทำให้เป็นทีมปอบถาวร แม้ส่งการ์ดต่อแล้ว

### เงื่อนไขจบเกมในโค้ดปัจจุบัน

- **ปอบชนะ:** ยังมีผู้รอดชีวิต และผู้รอดชีวิตทั้งหมดเคยเป็นปอบ
- **ชาวบ้านชนะ:** ไม่มีการ์ดปอบที่ยังไม่เปิดเหลือในเกม และยังมีผู้รอดชีวิตที่ไม่เคยเป็นปอบ
- **เสมอ:** ไม่มีผู้รอดชีวิต
- **ยุติเกมกรณีคนออก:** มีเส้นทางจบเกมเมื่อคนออกหมดหรือเหลือไม่พอเล่น โดยบันทึกเหตุผลแยกจากผู้ชนะปกติ

จำนวน 4 คนเป็นขั้นต่ำสำหรับ **เริ่มเกม** ไม่ใช่เงื่อนไขจบเกมทันทีเมื่อผู้รอดชีวิตลดต่ำกว่า 4 คน

รายละเอียดที่ใช้ตัดสินจริงอยู่ใน `src/server/game/outcome.js` และการจัดการคนออกใน `src/server/game/rooms.js`

### กลุ่มการ์ด

- **แดง:** ข้อกล่าวหา (+1), หลักฐาน (+3), พยาน (+7)
- **เขียว:** แพะรับบาป คำสาป ข้อแก้ต่าง ช่วงชิง พันธนาการ และวางเพลิง
- **น้ำเงิน:** เครื่องเซ่น ที่หลบภัย พลังศรัทธา และผูกวิญญาณ
- **ดำ:** พิธีเซ่นไหว้และยามวิกาล
- **การ์ดชีวิต:** ชาวบ้าน ปอบ และหมอผี

จำนวนการ์ดในสำรับปรับตามจำนวนผู้เล่น ดูที่ `src/shared/cards.js` และอ่านความสามารถแต่ละใบได้จากปุ่มอธิบายการ์ดในเว็บ

## คำสั่งที่ใช้บ่อย

```bash
npm start                         # เปิด server; build 3D ก่อนเริ่ม
npm run dev                       # เปิดด้วย nodemon; build 3D ก่อนเริ่ม
npm run build:client              # build JavaScript, CSS และ 3D
npm run build:3d                  # build เฉพาะฉาก Three.js
npm run health                    # ตรวจไฟล์และ syntax
node scripts/check-witch-night.cjs # integration check ระบบกลางคืน
```

- `npm run build:render` เรียก build ฝั่ง client เช่นเดียวกัน
- `npm run build` ต่อด้วย `build:server` ซึ่งปัจจุบันแสดงข้อความเท่านั้น เพราะ server รันจาก source โดยตรง
- `npm test` ใช้ Jest พร้อม `--passWithNoTests` จึงอาจผ่านได้แม้ไม่มี test cases
- `npm run lint` มีอยู่ แต่การตั้งค่า ESLint เดิมยังใช้ `sourceType: script` จึงต้องปรับให้รองรับ ES modules ก่อนใช้เป็นเกณฑ์ตรวจทั้งโปรเจกต์
- `optimize:assets` ยังเป็น placeholder ไม่ได้บีบอัดรูปหรือเสียงให้

### สถานะการตรวจสอบ

มีสคริปต์ integration สำหรับมาร์ค/ยืนยันสังหารของปอบ และเอกสาร [TEST_CASES.md](docs/TEST_CASES.md) สำหรับวางแผนทดสอบ เอกสารสถานการณ์ทดสอบไม่ใช่ผลยืนยันว่าทุกกรณีผ่านแล้ว

หลัง refactor มีการตรวจ syntax และ build แล้ว แต่ยังต้องทดสอบเล่นจริงตลอดเกมสำหรับโครงสร้างใหม่ การ build ผ่านไม่ยืนยันว่าทุกฟีเจอร์หรือทุกอุปกรณ์ทำงานครบ

## Deploy บน Render

ใช้ Web Service ที่รัน Node.js จาก repository นี้:

```text
Build Command: npm ci --include=dev
Start Command: npm start
```

`npm ci --include=dev` ใช้ `package-lock.json` ติดตั้งเครื่องมือ build และเรียก `postinstall` เพื่อ build หน้าเว็บกับ 3D

- ใช้ Node.js 24 ให้ตรงกับตัวอย่างการพัฒนา
- server อ่านพอร์ตจาก `PORT` ของระบบ โดยมีค่าเริ่มต้น 3000
- หน้าเว็บปัจจุบันให้บริการจาก `public/` ด้วย native ES modules ส่วน webpack ยังสร้าง `dist/` ได้
- ต้องเป็น server ที่รัน Node.js และ Socket.IO จึงจะสร้างห้องและเล่นหลายคนได้
- ห้องและเกมเก็บในหน่วยความจำของ process การ restart หรือ deploy ใหม่ทำให้ห้องเดิมหาย
- โครงสร้างปัจจุบันใช้ room store ใน process เดียว หากขยายหลาย instance ต้องออกแบบ shared state และการเชื่อมต่อเพิ่มเติม

ไม่ควรแก้ `dist/`, `public/table3d.bundle.js` หรือ `node_modules` โดยตรง ให้แก้ source แล้ว build ใหม่
